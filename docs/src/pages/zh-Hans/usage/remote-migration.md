# 迁移你的云存储

一些功能，例如[非对称存储](../deep-dive/asymmetric-storage)和[加密](../deep-dive/modules/encryption)，要求远端存储采用不同的格式。当你开启这些功能但远端仍是不兼容的格式时，Sync Engine 可能产生灾难性的同步结果。

Sync Engine 自身不会尝试自动迁移远端格式。原因是同步策略可能因设备而异，一台设备上的 Sync Engine 无法可靠地完成迁移，还可能把远端或其他设备留在损坏的中间状态。这一点将来可能改进，但目前开启这些功能时必须手动迁移。

本页详述如何用 Sync Engine 安全地完成手动迁移。

## 步骤

1. 在所有设备上执行同步，确保它们都持有最新的文件集合。
2. 选择文件最多、网络最好的一台设备作为主操作设备，在其余设备上退出 Obsidian。
3. 在这台设备上临时关闭实时同步和定时同步，避免意外干扰。
4. 临时调整[同步策略](./settings#同步策略)并执行同步，确保这台设备上的仓库持有你需要上传到远端的**完整文件集合**。完成后，调整同步策略，确保**"镜像本地"策略应用到这整个文件集合**。
5. **在开发设置中找到[清除记录](./settings#清除记录)，点击"清除"**。
6. 把整个文件集合复制到别处作为备份。
7. 进入云存储的文件管理界面，**手动删除所有之前同步过的文件，或直接删除根目录**。
8. 开启改变远端格式的功能（例如加密或非对称存储），应该会弹出迁移提醒，点击"确认"。
9. 现在触发一次手动同步，应该会显示一个充满上传操作的预览。检查要上传的文件并开始同步，等待批量上传完成。
10. **关闭其他所有设备的网络连接，并在每台设备上进入 Obsidian**，开启你要迁移的同一个功能。
11. 恢复这些设备的网络连接，各自启动一次手动试同步。同步应以 "已是最新状态" 完成，没有额外操作。
12. 在主设备上恢复同步策略和实时 / 定时同步设置。迁移到此完成。
