# Rclone S3 Timestamp 模块

当 Sync Engine 使用 S3 后端搭配 [`rclone serve s3`](https://rclone.org/commands/rclone_serve_s3/) 时，本模块保留文件的修改时间。选择 S3 后端时它自动生效。

## 修改时间

Sync Engine 以毫秒存储 `mtime`，而 rclone 把 `x-amz-meta-mtime` 解释为 Unix 秒。模块在线路上双向转换这个头：上传把毫秒转换为秒（例如 `1700000123456` 转为 `1700000123.456`），下载把秒转换回毫秒。

转换只作用于可解析的值：上传只转换形如 Sync Engine 时间戳的值（13 位毫秒）；下载只转换数值。服务器重启导致 `rclone serve s3` 丢失内存元数据、省略 `x-amz-meta-mtime` 时，S3 后端会自行从 `Last-Modified` 恢复时间。

## 加密

启用[加密](./encryption)时，其包装器（优先级 7919）在 S3 后端把元数据变成 `x-amz-meta-*` 头之前先加密元数据。加密后的 `mtime` 不是数值，因此本模块保持它不变；解密在读回时恢复毫秒值。

## 实现

模块以优先级 `307` 注册远端请求中间件，位于 S3 SigV4 中间件（`304`）之外，让请求签名覆盖转换后的值；位于重试中间件（`2000`）之内，让每次重试都从原始参数转换。中间件重建请求和响应而不是原地修改，其余每个头都不受影响。
