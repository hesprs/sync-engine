# 核心同步流程

核心同步流程由 `packages/plugin/src/modules/Sync.ts` 中的 `Sync` 实现。它按同步策略给本地和远端状态分桶，把每个桶与持久的记录存储比较，创建任务计划，并针对[文件系统抽象](./file-system)执行计划。

## 同步触发器

调度器接收来自手动控制、[实时同步](../usage/settings#实时同步)、[聚焦同步](../usage/settings#聚焦同步)、[启动同步](../usage/settings#启动同步)和[定时同步](../usage/settings#定时同步)的请求。触发器名称是 `manual`、`nonInteractiveManual`、`realtime`、`focus`、`startup` 和 `interval`。

每个触发器名称可以携带一个已注册条目，带优先级和选项工厂。待处理请求等待插件空闲，然后冲刷成一次同步：调度器把批次的触发器名称归约到优先级最高的条目，由该条目的 `options()` 定制这次运行。没有已注册条目的批次回退到 `unknown` 触发器并使用默认选项。批次中的每个请求得到相同的结果。

内置条目由 Bootstrap 注册：`realtime`（优先级 1000）换入快速远端列表器，当[实时同步快速模式](../usage/settings#实时同步快速模式)启用且缓存有条目时，复用缓存的 `remoteContext20000` 状态，跳过新的远端遍历；`interval`（2000）、`focus`（2500）、`startup`（3000）和 `realtime` 在[自动同步确认删除](../usage/settings#自动同步确认删除)启用时请求本地删除确认；`nonInteractiveManual`（3990）以默认选项运行；`manual`（4000）在[手动同步确认操作](../usage/settings#手动同步确认操作)启用时请求任务确认。非交互式手动命令使用单独的触发器，以便跳过手动任务确认。

实时事件在调度请求之前先做防抖和过滤。同步执行期间发生的变更会被忽略。重命名在其旧路径或新路径任一处于范围内时调度请求；规则配置见[同步策略规则](../usage/settings#同步策略规则)。

## 取消

每次运行创建一个取消引用。停止控件、进度弹窗、确认对话框和插件清理都会发布 `syncCanceled`。流程在遍历、规划、确认和执行之间检查该引用。[取消包装器](./file-system-wrappers#cancellation-wrapper)和[取消请求中间件](./request-middleware#cancellation-middleware)在文件系统和请求层强制执行它。

取消不回滚已完成的操作。取消之后抛出的任务错误会被忽略，但执行会等待任务 promise settle 之后才报告 `cancelled`。

## 遍历与策略匹配

基础设施初始化之后，流程发布 `syncInitialized`，附带本次运行的 `Infras` 和编译好的匹配器。

流程只编译一次配置的策略规则，然后并发开始本地和远端发现。本地遍历用匹配器调用 `localFs.list('/')`。完整远端遍历接收一个 reporter，转发进度并对每个上报路径应用匹配器。

默认远端列表器执行完整遍历。如果远端根目录不存在，它重建根目录、清除该本地 / 远端配对的记录并返回空列表。

匹配器把每个路径解析为一个策略名称加一个 `advance` 标志。对文件，策略单独决定归属。对文件夹，`advance` 控制遍历：被同步的文件夹会被遍历，其后代继承它的策略，除非后面的兜底 `none` 规则遮蔽了它；自身不被同步、但可能包含后续规则匹配内容的文件夹会作为探针被遍历。reporter 把这些结果映射为后端 `list()` 的 `include`、`exclude` 或 `advance`。规则语法与优先级记录在[同步策略规则](../usage/settings#同步策略规则)。

发现之后，超过配置的[最大文件大小](../usage/settings#最大文件大小)的条目被移除。不含任何被同步后代的探针文件夹被剪除；含有的则保留在保留策略 `none` 之下。剩余状态被组织为按策略分桶的结构：本地和远端状态用 `Record<string, StatsMap>`，记录用 `Record<string, RecordStatsMap>`。

## 决策器

规划由策略驱动。`decideTasks` 遍历按策略划分的映射，为每个策略名称查找已注册的决策器，策略没有决策器时以 `syncStrategyNotInstalled` 错误失败。每个决策器只接收自己的桶：`localStats`、`remoteStats`、`records` 和一个 `taskFactory`，它的任务被串联进本次运行的任务计划。保留策略 `none` 有内置的 pholder 决策器，只创建缺失的祖先文件夹，让位于未同步祖先之下的被同步后代能在两侧传输。

内置策略由 Bootstrap 注册，并可在[同步策略](../usage/settings#同步策略)规则中选择：

**双向同步策略**：

对文件，它把当前状态与记录的本地和远端 UID 比较。根据哪一侧存在、哪一侧变更，创建上传、下载、本地删除、远端删除、记录或冲突任务。两侧都存在但没有记录时，大小相等的文件只创建记录；大小不等的成为冲突。两侧都缺失的条目产生记录删除任务。

文件夹产生目录创建、删除或记录任务。本地 / 远端的文件-文件夹错配在可以判定时替换变更的一侧；无法判定的错配使规划失败。

**镜像本地 / 镜像远端同步策略**：

这两个决策器让一侧成为权威。它们复制权威侧的文件、创建权威侧的文件夹、删除只存在于另一侧的条目，并替换文件-文件夹错配。匹配的记录避免冗余的文件传输。键和大小都匹配但没有记录的文件会获得记录；其他没有记录的文件从权威侧复制。

## 移动检测

除非运行禁用了它，移动检测在决策器之后运行。它把同一侧的一个删除任务与一个创建任务配对（记录的 / 当前的文件 UID 匹配），然后把这对替换为 `moveLocal` 或 `moveRemote`。

它反复寻找文件夹的删除 / 创建对。只有每个相关子项都有兼容的移动、进入同一目的地且保留基名时，文件夹对才会被转换。没有记录身份的新文件、不完整的子计划和不明确的目的地保持为普通的删除 / 创建操作。

## 确认

两个确认闸门在移动检测之后、任务执行之前运行。手动任务确认由 `manual` 触发器条目在[手动同步确认操作](../usage/settings#手动同步确认操作)启用时请求。添加记录和删除记录的任务不显示在列表中；取消对话框即取消本次运行。

自动本地删除确认由 `realtime`、`interval`、`focus` 和 `startup` 触发器条目在[自动同步确认删除](../usage/settings#自动同步确认删除)启用时请求。对话框包含 `removeLocal` 任务。选择重新上传会变成上传或远端目录创建任务。

两种确认都会在进度弹窗中挂载一个[文件树](./file-tree)组件。

## 冲突解决器

冲突任务把 `key`、本地和远端文件状态、两个文件系统和记录存储传给所选的解决器。解决器由模块注册，按[冲突解决策略](../usage/settings#冲突解决策略)选择。内置策略及其面向用户的行为记录在该页。
