从 V2 迁移 ​

Sync Engine v3 发布于 2026 年 8 月 7 日，它的前身是已在生产环境运行数月的 "WebDAV Sync"。从 v2 到 v3 是一次围绕模块化和性能的完全重写；很多内容完全改变了，包括远端文件结构、存储模式、加密方案和插件设置。仍在使用 v2 的所有用户都需要迁移。

自动迁移 ​

WebDAV Sync 的最后两个版本（v2.5.12 和 v2.5.13）包含一套完整的迁移流程，可以无缝地把 WebDAV Sync 转换为 Sync Engine。

每次启动时，插件会请求 GitHub API 确认 hesprs/sync-engine 仓库是否存在，并把该仓库的存在视为 Sync Engine 已发布的信号。如果仓库存在，插件会打开一个弹窗提示你迁移到 Sync Engine。弹窗有三个选项：

  • 继续：开始迁移
  • 取消：下次插件启动时再次提示迁移
  • 不再显示：永久静默迁移提示，WebDAV Sync 保持原样继续工作。你可以在插件设置中进入迁移流程。

如果你开始了迁移，它会执行以下步骤：

  1. 先执行一次同步，确保你的仓库状态与远端一致。
  2. 以只读方式遍历 WebDAV，获取每个文件必要的 Etag，Sync Engine 用它标识文件唯一性。
  3. 访问 Sync Engine 模块源 https://sync.consensia.cc/modules.json，为你下载所需的模块。下载哪些模块取决于你在 WebDAV Sync 中用到的功能：
    • 非英语用户需要的受支持 i18n 模块。
    • 启用了加密时的加密模块。
    • 冲突策略为 "Smart merge" 时的智能合并模块。
  4. 把现有的同步记录复制并转换到 Sync Engine 的存储中。
  5. 只有以上步骤全部成功，本地记录才会被删除。随后你会收到提示，去 Obsidian 插件商店下载 Sync Engine。

步骤 1-4 中任何一步失败，迁移都会立即回滚，不会有数据丢失。

由于加密方案完全重做，Sync Engine 的加密模块无法再读取 WebDAV Sync 加密的文件。如果你在用加密，需要删除远端根目录，并在 Sync Engine 中重新同步整个仓库。如果没有用加密，你只需要从 Obsidian 模块商店下载 Sync Engine 并禁用 WebDAV Sync，之后就完成了。

为了迁移顺畅，如果你没有使用加密，Sync Engine 最精妙的功能锚定非对称存储默认关闭（启用加密时它会保持开启，因为无论如何你都要重新同步整个仓库）。你可以开启它并按照远程迁移指南手动转换你的仓库，之后的每次同步都会被这项技术加速。

版本 2.5.14 ​

更早的版本在遇到大型仓库时可能有性能问题，导致迁移失败。这是设计缺陷，已在 2.5.14 修复。如果你发现迁移在第 5 步失败，报错类似 net::ERR_INSUFFICIENT_RESOURCES，请点击这里下载修复后的版本，替换 <你的仓库>/.obsidian/plugins/webdav-sync/main.js，然后重试迁移。

手动迁移 ​

如果你想要一个更透明的迁移过程，能看清你的数据发生了什么，可以选择手动迁移。你需要完成以下全部步骤：

  1. 进入 Obsidian，用 WebDAV Sync 同步你的所有设备，确保它们持有一致的数据副本。如果出现迁移提示，直接选择"取消"。
  2. 在所有设备上禁用并删除 WebDAV Sync。
  3. 从 Obsidian 插件商店安装 Sync Engine。
  4. 在 Sync Engine 设置的模块管理页面安装 WebDAV 模块，并在所有设备上配置你的账户。
  5. 如果你之前启用了加密，请下载加密模块并配置加密密码，然后在 WebDAV 管理界面手动删除远端根目录。选择一台网络条件较好的设备，把加密的完整仓库同步到远端。
  6. 如果你之前没有使用加密，进入 Sync Engine 设置关闭"非对称存储"，你不需要在任何地方删除任何数据。
  7. 在其他所有设备上执行同步。Sync Engine 会扫描远端文件夹并采纳一致的状态，只填充内部记录，并显示 "已是最新状态"。
