设置 ​

打开 设置 > Sync Engine 修改这些选项。

部分设置由模块注册，它们的用法记录在对应模块的页面中。

核心 ​

存储后端 ​

选择将 Sync Engine 连接到你的存储服务的已安装模块。选择器旁边的连接图标会检查所选服务是否可达，每 10 秒自动刷新一次；点击图标也可以手动触发一次连通性检查。需要时，在对应模块的设置中配置所选服务。查看可用模块了解支持的存储后端。

模块管理 ​

打开模块管理页面。在这里，你可以从模块源、本地文件或粘贴的代码安装模块，也可以更新、启用、禁用、移除或编辑模块。模块提供存储后端和额外的同步策略。从不受你控制的模块源安装模块前，请先阅读安全一页。

模块管理页面包含一个搜索栏、一个只显示已安装模块的过滤器、从文件安装和从代码安装的入口、一个刷新模块源的入口，以及模块卡片。模块源 URL 在开发下的 模块源 页面中编辑。

自动更新模块 ​

从模块配置的源自动更新已安装的模块。默认开启。想手动审查每次更新时可以关闭它。

同步策略 ​

策略规则决定 Sync Engine 对每个文件和文件夹做什么。每条规则由一个 glob 表达式搭配一个策略组成：

  • 双向同步 是默认策略。它可以在两侧应用变更，并让所选的冲突解决策略处理文件被同时修改的情况。
  • 镜像本地 让本地仓库成为权威一侧。它把本地条目复制到远端，并删除只存在于远端的条目。
  • 镜像远程 让远端存储成为权威一侧。它把远端条目复制到本地，并删除只存在于本地的条目。
  • 不同步 让匹配的文件和文件夹完全脱离同步。

规则构成一个有序列表，最后一条匹配的规则生效。规则的求值方式和写法见同步策略规则。

镜像策略会直接覆盖非权威一侧的变更，不做冲突解决。模块可以提供额外的策略；安装后会出现在规则的下拉选项中。

冲突解决策略 ​

选择当同一个文件在上次成功同步之后被本地和远端同时修改时，如何处理。可选项包括：

  • 重命名并保留两者：通过把较旧的版本重命名为 <原始文件名>.conflict.<扩展名> 来保留两个版本。这是默认选项，避免静默丢失任何一个版本。
  • 保留最新修改：保留修改时间更新的版本。
  • 保留本地：用本地版本替换远端版本。
  • 保留远程：用远端版本替换本地版本。
  • 跳过：冲突保持不变，直到你用其他方式解决它。

选择与你工作方式匹配的策略。当时间戳错误或设备之间时钟不一致时，替换类和保留最新类的选项可能丢弃变更。可选的智能合并模块为受支持的文件提供文本合并策略。

功能 ​

实时同步 ​

文件发生变化后自动开始一次同步。填写最后一次文件变化到开始同步之间的延迟，例如 500ms 或 5s。如果你在短时间内连续编辑多个文件，Sync Engine 会等待延迟结束后再同步，而不是为每次编辑各开一次同步。

默认关闭。存储的默认延迟为 5s。

启动同步 ​

插件加载后自动开始一次同步。填写启动后等待的时长，例如 5s 或 1min。

默认关闭。存储的默认延迟为 5s。

定时同步 ​

按固定间隔反复开始同步。填写间隔，例如 10min 或 0.5h。适合不想对每次编辑做出反应、只需要定期同步的场景。

默认关闭。默认间隔为 15min。间隔必须大于零。

焦点同步 ​

当你切回 Obsidian 时开始一次同步，让另一台设备或其他工具做出的修改无需等待下一次定时同步即可到达。填写两次同步之间的最小间隔，例如 30s 或 1min。同步进行中，或距上次同步结束不足这个时间时，焦点同步会被跳过，避免频繁切换窗口时反复同步。

默认关闭。默认最小间隔为 5min。不希望启用它的设备（例如手机）可以单独关闭。

实时同步快速模式 ​

在实时同步时复用最近缓存的远端信息，跳过一部分远端发现工作。这可以让快速编辑更快地同步完成，对远端文件夹很大的情况尤其明显。

默认开启。当实时同步必须每次都做完整的远端检查时（例如文件经常在 Obsidian 之外被修改），可以关闭它。

非对称存储 ​

远端文件不再镜像你仓库的文件夹结构，而是以生成的名称平铺存储。Sync Engine 用自己的记录还原原始的本地路径。这可以显著加快同步，也能减少存储服务在处理大型文件夹树上的开销。

这会改变远端存储的外观。开启之前，请阅读单独的非对称存储指南了解其设计与限制：

  • 远端文件无法以正常的文件夹结构阅读。
  • 使用该仓库的每台设备都必须使用相同的设置。
  • 对已有仓库更改此设置会弹出确认提示。取消则保持当前设置不变。
  • Sync Engine 不会自动迁移远端存储。确认后设置只作用于之后的同步；已有的远端文件保持原来的布局。确认前请阅读远程迁移指南。
  • 只有在你不需要把远端文件当普通文件浏览时才开启它。

默认开启。

控制 ​

这些选项限制同步占用的资源。对有请求限制的存储服务很有用。

最大文件大小 ​

跳过超过所填上限的文件。这不会修改或删除文件，只是不把它纳入同步操作。

默认关闭。存储的默认上限为 30MB。

最大并发请求数 ​

限制同时进行的远端请求数量。调低有助于拒绝过多并发请求的服务；服务和网络允许时，调高可以提升速度。

默认开启，上限为 50 个请求。

最小请求间隔 ​

要求远端请求之间有最小的等待时间。服务强制每秒请求上限时使用。它与 最大并发请求数 配合：后者限制同时进行的工作，这个选项把请求在时间上拉开。

默认关闭。存储的默认间隔为 0。

数值格式 ​

  • 文件大小接受 B、KB、MB、GB 或 TB，例如 10MB 或 0.5GB。
  • 时间值接受 ms、s、min、h 或 d，例如 500ms、5s 或 1h。
  • 请求并发数等数值接受一个数字，例如 50。
  • 数值必须大于等于零。表示上限或间隔的设置可能拒绝零。无效的值会以警告标记，修正之前不会被保存。

同步策略规则 ​

规则在同步策略页面中按有序列表管理。每条规则由一个 glob 表达式搭配一个策略组成。多条规则匹配同一路径时，最后一条匹配的规则生效。没有匹配任何规则的路径不会被同步。

Sync Engine 自带默认规则：对所有内容（*）双向同步，外加针对常见噪音的 不同步 规则，例如 .git、.trash、.obsidian、系统元数据文件、Office 临时文件，以及 Sync Engine 自己的 modules 文件夹。你可以编辑、重排或扩展这些规则。

  • 匹配文件夹的规则会把策略应用到文件夹内的所有内容。
  • 更靠后的规则可以单独指定该文件夹内的路径，给它们不同的策略。

示例：同步所有内容，让一个私密文件夹脱离同步，但保留其中一个共享子文件夹继续同步：

顺序规则策略
1*双向同步
2private/不同步
3private/shared/**/*双向同步

规则 2 排除了 private/ 下的所有内容。规则 3 更靠后，所以 private/shared/ 下的文件仍然会同步。

WARNING

Sync Engine 的模块文件位于 .obsidian/plugins/sync-engine/modules。如果你的规则让这个文件夹参与同步，任何 Sync Engine 不知道的修改（包括同步运行本身造成的修改）都会触发安全保护机制，模块将停止加载。默认规则完整排除了 .obsidian；请保留这个排除项，或者确保你的规则永远不会同步 modules 文件夹。

编写规则 ​

规则使用 glob 表达式：

规则匹配
*.log仓库中任意位置的日志文件
temp/名为 temp 的文件夹及其内容
notes/**/*.mdnotes 及其子文件夹内的 Markdown 文件
test-files/**/*test-files 及其子文件夹内的全部内容
.trash/任何名为 .trash 的文件夹
*.{png,jpg}仓库中任意位置的 png 或 jpg 文件
/.obsidian/仓库根目录的 .obsidian
  • * 匹配单个路径段内的任意字符。
  • ** 匹配任意数量的路径段，包括零个。
  • ? 匹配一个字符。
  • [abc] 匹配集合中的一个字符。
  • [!abc] 匹配集合之外的一个字符。
  • {a,b,c} 匹配列出的任意一种，花括号可以嵌套。
  • 规则以 / 结尾时只匹配文件夹。
  • 规则以 / 开头时从仓库根目录开始匹配；否则在任意深度匹配。
  • 规则区分大小写：Temp 不匹配 temp。

TIP

Sync Engine 会避免遍历不可能包含同步内容的子树。当一个 不同步 文件夹不可能包含任何被后续规则匹配的内容时，遍历在这个文件夹处停止。如果后续规则可能匹配到它的后代，Sync Engine 会探查该文件夹来找到被包含的内容。

在位置已知时使用锚定规则。例如，当 projects 位于仓库根目录时，用 /projects/current/**/* 而不是 projects/current/**/*。锚定规则立即缩小了可能的路径范围，减少了对无关文件夹的探查，从而加快遍历。未锚定的规则可以在任意深度匹配同样的路径形态，可能需要更多遍历。

杂项 ​

自定义请求头 ​

向发送到远端存储服务的每个请求添加 HTTP 头。一些服务用请求头传递租户名、API 版本或其他账户相关的选项。

非敏感的值用明文请求头。令牌等私有值用密文请求头；密文值存储在 Obsidian 的钥匙串中，而不是普通插件设置里。Sync Engine 何时读取这些密文见运行时权限。请求头名称必须有效，并与存储服务要求的名称一致。空的请求头行在保存时会被忽略。

在可以使用密文请求头时，不要把凭据放进明文请求头。错误的请求头会让连接检查和同步失败。后端模块可能有自己的凭据设置，请遵循对应模块的文档。

移动端同步状态提示 ​

移动端在同步进行时显示通知。桌面端由状态栏显示同样的信息。

默认开启。

离线时避免自动同步 ​

设备没有连接任何有线或无线网络时，静默跳过所有非手动发起的同步。

默认开启。

手动同步时确认操作 ​

手动发起的同步在运行前显示计划执行的文件操作，你可以审查并确认。这不影响自动同步。

默认开启。

自动同步时确认删除 ​

自动同步删除本地文件前先询问。在确认窗口中，你可以接受删除，也可以选择改为重新上传这些文件。

默认开启。适用于实时、焦点、启动和定时同步。

开发 ​

这些操作主要用于排查问题，请谨慎使用。

清除记录 ​

Sync Engine 保存着本地与远端文件上次匹配情况的记录。它用这些记录区分新变更与冲突，并规划安全的同步操作。

点击 清除 按钮会移除当前后端 + 仓库组合的记录。

这些操作不会直接删除文件，但下一次同步可用的历史会变少，计划的上传、下载或删除可能因此不同。设置中的警告说明清除记录可能导致数据丢失。只有在你手动修改过远端文件、且插件已经报告了错误操作时才使用它。

导出日志到文件 ​

把 Sync Engine 的日志写入 <仓库根目录>/Sync Engine Logs/ 文件夹。报告一次失败的同步或排查连接问题时使用。日志可能包含路径和服务细节，分享前请先检查文件内容。

模块源 ​

编辑 Sync Engine 获取模块目录使用的 URL。URL 必须以 http: 或 https: 开头，无效的条目会保持标记，修正后才能生效；尽量使用 HTTPS。

默认源是 https://sync.consensia.cc/modules.json。对无法访问默认源的网络，可以使用 GitHub 托管的备用源 https://raw.githubusercontent.com/hesprs/sync-engine/refs/heads/gh-pages/modules-alternative.json。同一时间只使用一个官方源，避免模块条目重复。
