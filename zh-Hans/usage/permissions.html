运行时权限 ​

本页完整列出 Sync Engine 和官方模块使用的、可能引起顾虑的运行时 API，并附上可验证的说明解释其必要性。你也可以把这份清单与 Obsidian Community 网站上插件评分卡中的 "Disclosure" 部分对照。

动态执行 JavaScript 模块 ​

动态执行 JavaScript 模块属于动态代码执行，与 Obsidian 加载插件的方式类似。它是 Sync Engine 可扩展架构的基础。

Sync Engine 只执行用户明确下载或批准的 JavaScript ESM 模块，而且只在插件启动、模块自动更新或用户显式操作时执行。

Sync Engine 实现了一系列机制来压缩模块执行带来的攻击面。详情见安全。

访问和修改仓库文件 ​

Sync Engine 为基本的同步和模块管理需求访问并修改仓库文件。

它读取每个文件的最后修改时间和大小来检测变更；读取文件并上传到配置的同步后端；并根据检测到的远端变更更新或删除本地文件。被删除的文件遵循 Obsidian 的垃圾桶设置，可能进入系统垃圾桶、仓库的垃圾桶文件夹，或被永久删除。

Sync Engine 只在同步运行期间访问和修改仓库文件，并且从不访问被不同步策略规则明确排除的文件。

Sync Engine 还会把模块保存在 <仓库文件夹>/.obsidian/plugins/sync-engine/modules/。

网络请求 ​

Sync Engine 只为以下两个目的发出网络请求：

  • 完成授权，并把文件同步到配置的后端
  • 获取模块源并下载模块

同步相关的请求只发生在同步运行期间。

模块源只在自动模块更新开始或用户打开模块管理页面时被获取。Sync Engine 只获取 "模块源" 设置中定义的模块源。模块只在用户手动下载模块或模块自动更新时被下载。

默认唯一的模块源是 https://sync.consensia.cc/modules.json。sync.consensia.cc 托管在 GitHub Pages 上，其源码 100% 透明，可在 Sync Engine 的 GitHub 仓库中验证。

Sync Engine 插件和 sync.consensia.cc 不包含任何形式的遥测。

Obsidian 密钥存储 ​

Obsidian 密钥存储在 Obsidian 设置中显示为 "Keychain"。Sync Engine 和官方模块在以下场景获取密钥：

  • 插件核心：同步运行开始时读取配置的密文请求头
  • WebDAV 模块：同步运行开始时读取配置的 WebDAV 密码密钥，用于服务认证
  • S3 模块：在连接检查或同步操作解析 S3 凭据时读取配置的密钥访问密钥
  • Google Drive 模块：自动管理名为 sync-engine-gdrive-refresh-token 的密钥，用它为连接检查和同步操作授权
  • Dropbox 模块：自动管理名为 sync-engine-dropbox-refresh-token 的密钥，用它为连接检查和同步操作授权
  • 加密 模块：同步运行开始时读取配置的加密密码密钥，用于之后的加密和解密

Sync Engine 和官方模块从不读取超出用户提供的范围。

IndexedDB 存储 ​

IndexedDB 是一个浏览器 API，把数据存在内嵌数据库而不是物理文件里。Sync Engine 通过 uni-kv 包使用 IndexedDB。

插件核心把 IndexedDB 用于以下目的：

  • 记录已知的本地和远端已同步文件的唯一标识，辅助下一次同步的三方变更检测
  • 记录每个已安装模块的元数据，包括启用状态和完整性哈希。IndexedDB 天然免疫常见的仓库文件替换攻击，Sync Engine 利用这一点，把模块执行限制在用户批准过的模块上
