智能合并模块 ​

智能合并是一个面向文本文件的可选文本冲突解决器。它为每个可合并的文件保存一份基础快照，然后用这份快照区分独立编辑与冲突编辑。模块注册一个远端文件系统包装器、smartMerge 冲突解决器和设置。

支持的文件与注册 ​

去除首尾空格并转小写后以 .md、.markdown 或 .txt 结尾的路径才是可合并的。其他文件直接透传，不做基础文本跟踪。

模块以优先级 20_098 包装远端文件系统。包装器把正常的文件系统行为委托给被包装的实例，并增加基础快照维护。解决器以 ID smartMerge 注册。

基础快照生命周期 ​

包装器为其本地 / 远端文件系统命名空间接收一个 uni-kv 的 StoreAsync<string>。这个 store 把文件键映射为纯文本快照。

  • write() 成功后，路径可合并时包装器把写入值存为文本。失败的写入不更新快照。
  • move() 成功后，已有快照从旧键移到新键。移到相同键不改变 store。
  • delete() 成功后，该键的快照被删除。
  • read()、readStream()、mkdir()、stat()、exists() 和 list() 保持原行为。

数据库 store 名为 base-text-<namespace>，namespace 与插件核心为本地和远端文件系统选择的命名空间相同。这防止快照在不相关的同步目标之间共享。

冲突解决流程 ​

解决器接收两个 FileStat、文件键、两个文件系统和同步记录存储。它并发读取本地内容、远端内容和存储的基础快照。

存在基础快照时：

  1. 把本地和远端内容解码为文本。
  2. 两个文本完全相同时，不写入任何一侧；只用现有 UID 刷新同步记录。
  3. 否则合并三个文本：本地为 a，远端为 b，存储快照为 o。
  4. 只把合并后的文本写入当前文本与之不同的那一侧。
  5. 记录得到的本地和远端 UID。

合并后文件的 mtime 设为 max(local.mtime, remote.mtime)。合并的 meta 把 ctime 保留为两侧最早的创建时间，mtime 设为合并时间，其余元数据字段取两侧的并集。

没有基础快照时，智能合并无法区分独立变更。它回退到保留最新（latest-survive）行为：把修改时间较新的一侧复制到另一侧。只有 local.mtime > remote.mtime 时本地获胜；时间戳相等选择远端侧。回退使用 SDK 的传输辅助函数，大内容可以流式传输。

合并模型 ​

合并算法是递归的 diff3 合并。它面向文本，不感知 Markdown AST，并在多个粒度上工作：

  • 文档层级上，它把内容切成非空行，并保留行之间的换行序列。
  • 以三个反引号、~~~ 或 $$ 开头的围栏块按代码拆分并逐行比较。它们的开始和结束围栏保留在合并内容中。
  • 正文按单词和标点切分，空白保留在 token 之间的接缝处。对通常不带空格书写的文字，它使用 Intl.Segmenter 并自动检测日语、中文、泰语、老挝语、高棉语、缅甸语和藏语文本。

对每个 diff3 区域，算法应用这些规则：

  • 本地与远端相等时，保留该值。
  • 一侧仍等于基础时，保留另一侧的变更。
  • 两侧以不同方式修改了同一区域时，产生一个冲突。
  • 冲突区域可以在更细粒度上拆分时，先递归再产生标记。这让同一行或同一代码块内互不相关的编辑可以独立合并。

组合区域时，空白和换行接缝保留自源区间。算法不尝试对结果文档做语义或语法校验。

冲突标记 ​

冲突内容直接写入合并后的文件。普通的双侧冲突表示为被 ours 标记包裹的本地内容，后接被 theirs 标记包裹的远端内容。一侧删除内容、另一侧修改时，幸存内容由删除标记包裹。

默认标记：

用途开始结束
本地 (ours)<mark class="conflict ours"></mark>
远端 (theirs)<mark class="conflict theirs"></mark>
删除<mark class="conflict deleted"></mark>

用户可以在智能合并设置中独立配置全部六个标记字符串。修改会更新模块设置并通过插件设置存储持久化。
