Dropbox 模块 ​

Dropbox 模块注册 dropbox 远端文件系统。它把仓库存储在一个 Dropbox 应用的应用文件夹（app folder）内，通过 Dropbox 公开 API 执行文件操作。模块使用带 PKCE 的 Dropbox OAuth 2.0 认证，不使用第三方服务器或代理。

设置 ​

模块添加一个 Dropbox 设置分组。在选择 Dropbox 作为远端文件系统之前，先配置这些设置：

连接账户 / 账户已连接 ​

这个设置发起 Dropbox 授权流程。授权后，模块把刷新令牌安全地存入 Obsidian 的密钥存储，并按需用它换取短期访问令牌。Disconnect 选项向 Dropbox 撤销该令牌组、把它从密钥存储移除、清除所有缓存的访问令牌，并删除存储的账户标识。

WARNING

连接 Dropbox 账户会在 Obsidian 钥匙串中创建一个名为 sync-engine-dropbox-refresh-token 的新密钥。这个密钥完全由 Sync Engine 管理，用作换取 Dropbox 访问令牌的刷新令牌。请勿将它用于其他用途。

基目录 ​

这定义 Dropbox 应用文件夹内作为该仓库根目录的文件夹。该值按目录路径规范化。留空时保持为 /，即应用文件夹的根。指定的文件夹在第一次同步时自动创建。

WARNING

基目录位于应用文件夹内，这是一个由应用管理的命名空间（在 Dropbox 网页界面显示为 Applications/<应用名>）。模块只能看到并操作自己应用文件夹内的文件。应用文件夹之外的文件或文件夹对这个模块不可见。

删除到垃圾桶 ​

启用时，远端删除的文件被移入 Dropbox 垃圾桶而不是永久移除。禁用时，被删除的文件立即永久清除。注意 Dropbox 通常在 30 天后清空垃圾桶中的条目。

认证流程 ​

模块使用带 PKCE (S256) 和自定义 obsidian:// 重定向的 OAuth 2.0 授权码流程，Dropbox 在桌面和移动端都支持它：

  1. 点击 Connect 时，模块生成一个 code verifier 及其 S256 challenge，外加一个随机 state 值，然后显示一个带 Open Dropbox 按钮的对话框。
  2. 该按钮在系统浏览器中打开 Dropbox 的授权页面。页面请求离线访问，外加下面列出的全部 scope。在那里批准访问。
  3. Dropbox 重定向到 obsidian://sync-engine-dropbox-auth?code=...&state=...，重新打开 Obsidian 并把回调交给模块。模块验证 state 值与待处理请求一致，然后携带 PKCE verifier 在 Dropbox 的令牌端点交换授权码。
  4. Dropbox 返回短期访问令牌、刷新令牌和账户 id。模块把刷新令牌存入 Obsidian 的密钥存储，并把访问令牌缓存在内存中。
  5. 之后的 Dropbox 请求使用缓存的访问令牌。接近过期时，模块用刷新令牌换取新的访问令牌。HTTP 401 的失败请求会触发一次强制刷新并重试。

任何环节都不涉及 client secret：PKCE 取代了它，这是 Obsidian 这类公共客户端的推荐模式。state 值防范过期或不匹配的回调，因此来自其他仓库窗口的残留重定向会被忽略。

权限与范围 ​

模块的 Dropbox 应用使用 App folder 权限类型，只请求这几个 OAuth scope：

files.metadata.read ​

让模块列出自己的文件并读取元数据，以发现远端变更、检查连接和解析路径。

files.content.read ​

让模块从自己的应用文件夹下载文件内容。

files.content.write ​

让模块上传文件内容、创建文件夹，并在自己的应用文件夹内删除、移动或重命名文件。

App folder 权限是刻意的最小权限选择：模块只能管理它在自己应用文件夹内创建的数据。你的 Dropbox 其余部分，包括你共享或存储在应用文件夹之外的文件，对模块永远不可见，模块也没有账户级访问权限。

文件元数据 ​

Dropbox 对应用文件夹类应用没有自定义键值元数据（文件属性 API 明确排除它们），因此模块存储 API 本身携带的信息：

  • 文件修改时间通过上传时的 client_modified 保留，并通过 stat() 和 list() 读回。API 以秒精度存储时间戳。
  • 文件创建时间和所有文件夹时间戳不被 Dropbox API 保留；文件还原到设备时会回退为本地创建的时间。
  • 文件身份使用 Dropbox 的 content_hash，即 API 返回的由内容派生的哈希。

大小写敏感性 ​

Dropbox 路径不区分大小写，但保留大小写。仅大小写不同的两个本地文件无法在应用文件夹中共存；模块无法在远端把它们区分开，因此该后端不支持包含仅大小写差异重名的仓库。仅大小写的重命名通过一个临时中间名执行，因为 Dropbox 的移动端点直接拒绝它们。

批量操作 ​

模块自带一个远端优化器，为 Dropbox 替换插件的层级优化器。它保留层级语义（祖先排序、伞状归并、移动门控），并额外把符合条件的删除、移动和文件夹创建合并到对应的 Dropbox 批量端点（delete_batch、move_batch_v2、create_folder_batch），而不是每个文件发一个请求。Dropbox 异步应答的批量任务会被轮询直到完成，逐条目的失败只 reject 它所属的任务。会在同一次批量调用内冲突的移动，以及仅大小写的重命名，都单独执行。

下载和上传不批量：write() 用单个上传请求，writeStream() 用并发的上传会话（4 路并行的 4 MiB 对齐追加），下载通过对齐的 HTTP range 请求流式传输。

隐私政策 ​

最后更新于 2026 年 11 月 3 日。

引言 ​

本隐私政策说明 Obsidian 的 Sync Engine 插件与 Dropbox 模块（下称"插件"）在你连接 Dropbox 账户时如何处理你的数据。插件是 MIT 协议授权的开源软件。

我们收集的数据 ​

我们不收集任何数据。 插件没有遥测、没有分析、没有远程日志服务，也没有后端服务器。任何关于你、你的文件或你的使用情况的信息都不会离开你的本地设备。

你的数据如何被处理 ​

Dropbox 账户连接：

点击 "Connect" 时，插件直接从你的设备打开 Dropbox 的授权页面。插件只请求以下 scope，且限定于它自己的应用文件夹：

  • files.metadata.read：读取应用文件夹内的文件和文件夹元数据
  • files.content.read：从应用文件夹下载文件内容
  • files.content.write：在应用文件夹内上传、创建、移动和删除文件

你的 Dropbox 其余部分对插件永远不可见。

令牌存储：

OAuth 刷新令牌只存储在你本地设备的 Obsidian 加密密钥存储中。令牌从不传输给任何第三方，从不记录日志，也从不出现在崩溃报告或诊断信息中。

文件操作：

所有同步操作都由你手动触发或调度。文件读写直接发生在你的本地 Obsidian 仓库与 Dropbox 之间，经 Dropbox 的 API 完成。没有任何中间服务器参与。

数据保留：

你的数据只存在于你的本地设备和你的 Dropbox 账户中。点击 "Disconnect" 时，插件：

  1. 向 Dropbox 撤销 OAuth 令牌组
  2. 从 Obsidian 密钥存储删除所有已存储的令牌

断开连接后，你的设备上不会残留任何 Dropbox 账户连接的痕迹。

第三方 ​

涉及的唯一第三方服务是 Dropbox 的 OAuth 和文件 API，由你直接授权。除使用其公开 API 外，我们与 Dropbox 没有任何关系。我们不向任何实体共享、出售或转移任何数据。

你的权利 ​

你拥有完全的控制：

  • 所有数据都在你的本地设备上，随时可以检查
  • 点击 "Disconnect" 立即清除所有本地凭据
  • 随时在你的 Dropbox 账户的已连接应用设置中撤销访问
  • 无论插件状态如何，你的文件都保留在你的 Dropbox 中

变更 ​

本政策的更新将发布在插件的 GitHub 仓库和 https://sync.consensia.cc。变更后的继续使用视为接受。
