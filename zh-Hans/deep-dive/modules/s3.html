S3 模块 ​

S3 模块把 Sync Engine 连接到 Amazon S3 和实现 S3 API 的对象存储服务。它注册 s3 远端文件系统，并使用 SDK 的请求流水线完成认证、代理路由和其他请求中间件。

支持的后端 ​

模块支持：

  • Amazon S3
  • Cloudflare R2
  • 通过 S3 兼容 API 接入的 Backblaze B2
  • MinIO
  • RustFs
  • 阿里云 / 腾讯云对象存储
  • Wasabi
  • Rclone serve S3（仅 v1.76+，设置 --directory-markers 标志）
  • Ceph Object Gateway、DigitalOcean Spaces 以及其他 S3 兼容服务

兼容性取决于服务是否实现了所需能力与权限中列出的对象操作。部分服务要求 path-style URL 而不是 virtual-hosted URL。

设置与配置 ​

安装并启用 S3 模块，然后选择 S3 作为存储后端。配置这些模块设置：

设置说明
Endpoint URLS3 服务的 HTTP(S) 端点。
Region请求签名使用的存储桶区域。默认 us-east-1。
Access key ID用于认证的访问密钥。
Secret access key与访问密钥 ID 配对的秘密密钥。存储在 Obsidian 的钥匙串中。
Session token可选的临时会话令牌。存储在 Obsidian 的钥匙串中。
Bucket name存储仓库对象的存储桶。
URL styleVirtual-hosted 或 path-style 对象 URL。
Prefix把某个子目录暴露为仓库根的键前缀。默认 /。
Proxy URL可选的 S3 请求代理端点。默认关闭。

端点、区域、访问密钥 ID、存储桶和前缀值保存为模块设置。端点和代理值必须是合法 URL。前缀按目录键规范化，vault 变为 vault/。

凭据与钥匙串 ​

访问密钥 ID 存储在模块设置中。秘密访问密钥和可选的 AWS 会话令牌通过 Obsidian 的密钥存储输入，不作为普通模块设置存储。配置了会话令牌时，S3 模块以 x-amz-security-token 发送它，并把该头纳入 SigV4 签名。

URL 风格 ​

Virtual-hosted style 把存储桶放进主机名：

text
https://bucket.s3.example.com/path/to/file.md

Path style 把存储桶放进路径：

text
https://s3.example.com/bucket/path/to/file.md

默认使用 virtual-hosted style。服务不提供存储桶子域名、或其 DNS 和 TLS 配置要求时，使用 path style。

前缀 ​

前缀选择存储桶中暴露给 Sync Engine 的部分。前缀为 vault/ 时，本地键 Notes/today.md 存储为 vault/Notes/today.md；前缀本身对列表和文件状态隐藏。/ 暴露存储桶根目录。

前缀是可导入的 SDK prefixWrapper，应用于 S3 文件系统。包装器的一般行为见文件系统包装器。

代理 ​

S3 请求需要经过 HTTP(S) 代理或网关时，启用 Proxy URL。代理替换请求主机，保留原始路径和查询。SigV4 签名发生在这个重写之前，因此代理必须把已签名的请求转发到配置的 S3 端点，并保留它的签名头。

所需能力与权限 ​

给 S3 身份授予与这些操作等价的权限，作用于配置的存储桶和前缀：

  • ListBucket：检查连接和列出对象，包括分页列表
  • GetObject：下载对象、读取 range 对象数据、获取对象元数据用于文件状态
  • PutObject：上传对象和文件夹标记对象
  • DeleteObject：删除对象并清理被移动的对象
  • CopyObject：文件移动时复制源对象
  • 大文件流式写入所需的多部分上传权限：发起、上传分块、完成和中止多部分上传
  • DeleteObjects：优化的批量删除

各供应商的具体权限名称不同。策略可以把对象权限限定到配置的前缀，但存储桶列表权限也必须允许列出该前缀。

实际行为 ​

  • S3 只有对象，没有真实目录。mkdir() 创建一个以 / 结尾的零字节对象作为文件夹标记。
  • 移动使用 S3 复制后删除，因为 S3 没有原生的重命名操作。
  • 删除不存在的对象视为成功。其他服务错误会中止该操作。
  • 文件状态优先用 ETag。没有时，模块以修改时间和大小作为文件 UID 的回退。
  • 非对称存储可以压平并锚定远端键。只在远端文件不需要保持正常文件夹结构可读时使用，并在设备之间保持该设置一致。

对象元数据 ​

S3 把文件元数据存为 x-amz-meta-* 用户自定义头。文件 meta 非空时，write() 和多部分上传的发起会带上这些头。stat() 总是从 HEAD 响应提取 x-amz-meta-* 头。

S3 的 ListObject 不返回对象元数据，但 GetObject 和 HeadObject 返回。模块先尝试从之前缓存的 GET 请求中获取元数据，找不到时对每个列出的文件额外发一个 HEAD 请求获取元数据。

实现 ​

统一文件系统映射 ​

S3Fs 以统一键实现 SDK 的 RootFs 契约：/ 为根，folder/file.md 为文件，folder/ 为文件夹。对象键按路径段做 URL 编码。配置了前缀时，S3 模块在 S3Fs 外应用共享的 prefixWrapper。

基本操作到 S3 请求的映射如下：

文件系统操作S3 操作
read()GET 对象
write()PUT 对象
stat()HEAD 对象
delete()DELETE 对象
move()CopyObject，然后 DELETE
mkdir()PUT 零字节文件夹标记
list()ListObjectsV2

SigV4 中间件 ​

S3 是所选后端时，已注册的请求中间件用 AWS Signature Version 4 认证包装每个 S3 请求。它使用配置的访问密钥 ID、秘密访问密钥、区域和服务名 s3，对端点主机、方法、规范化路径、排序后的查询和请求头签名。

实现对载荷哈希发送 UNSIGNED-PAYLOAD，让请求抽象可以传递二进制 body 而不必缓冲它们来计算哈希。签名前存在的自定义头会纳入签名。

递归列表 ​

list() 使用带前缀的 S3 ListObjectsV2，而不是每个目录发一个请求。它跟随 NextContinuationToken 直到读完所有页，把每个返回的键上报给统一文件系统 reporter，并把以 / 结尾的键映射为文件夹。被请求的目录条目本身不出现在子项列表中。

Range 读取 ​

readStream() 在请求抽象之上用 range GET 请求工作。它请求 2 MiB 的分块，同时在途请求最多八个，缓冲的分块最多八个，即使响应乱序到达也按文件顺序发出分块。空文件返回一个已关闭的流。

多部分上传 ​

每个 writeStream() 都使用 S3 多部分上传。分块通常为 5 MiB；最后一块可以更小：

  1. 发起一次多部分上传。
  2. 读取 5 MiB 分块，最多三个并发上传。
  3. 按分块编号顺序用每个分块的 ETag 完成上传。

最后一块可以小于 5 MiB。失败时，进行中的分块上传完成或 settle，然后模块尝试中止这次多部分上传。

批量删除 ​

S3 优化器把删除原子替换为单个自定义原子，它的 batchDelete() 把键拆成每个最多 1000 个键的 DeleteObjects 请求。请求包含 XML 和 Content-MD5 头。服务结果按键处理：成功的键 resolve，S3 错误结果中报告的键逐个 reject。整个批量请求失败时，每个键用单独的 DELETE 请求重试并独立处理。
