基准测试 ​

基准测试标准 ​

基准测试旨在获得 Sync Engine 与其他同步插件之间可靠、可复现的同步性能与算法正确性统计。测试期间 Obsidian 实例只能安装被测插件。被测插件必须使用默认设置，以下情况除外：

  • 账户配置
  • 阻止同步非交互式进行的 UI 确认
  • 会导致最终结果出现正确性验证器意义上的"错误"的设置（大小上限 / 不同步特定文件 / ...）

每次基准测试都包含下述固定流程和测试用例，任何对测试流程的特殊偏离都必须清楚记录。

基准测试签名 ​

为确保可复现性，每次基准测试必须包含以下元数据：

  • 被测插件
  • Obsidian 版本
  • 被测插件版本
  • 测试机的操作系统（由于测试脚本的假设，不支持 Windows）
  • 测试机的 Geekbench 7 CPU 单核跑分（可在 Geekbench 网站搜索并估算平均值）
  • 被测远端后端类型与服务
  • 到被测服务的平均 ping 延迟（毫秒），使用 Ping 测试器
  • 被测服务的平均上传与下载速度（MiB/s）

概览统计 ​

插件体积：从对应版本的 GitHub 发布页获取。

透明：作者是否让每个可控组件保持透明。

启动速度：

在测试机上彻底杀掉 Obsidian Electron 应用并重启 5 次，每次记录 Obsidian 设置 -> General -> Advanced -> Notify if startup takes longer than expected -> 秒表图标 -> 被测插件的启动时间（毫秒）。然后取 5 次记录的平均值。

同步隐藏文件：插件能否（或能否配置为）同步以 . 开头的文件夹中的任意文件。例如 .obsidian/ 目录。（Obsidian 的 vault.* API 看不到这些文件，只有 vault.adapter.* 可以）

移动检测：插件能否正确识别本地和远端的文件移动，而不是把它们变成删除 + 上传 / 下载。

分块传输：插件读 / 写 / 下载 / 上传大文件时是否使用流或分块，不在内存中缓冲整个文件。这个特性决定了它能否在移动设备上传输大文件而不崩溃。

元数据同步：插件能否在跨设备同步时保留文件的最后修改时间 / 创建时间。

加密：插件是否支持客户端加密。

冲突解决：文件在本地和远端同时被修改时，解决冲突所用的方法。

测试用例 ​

上传速度：

用测试仓库引导器初始化一个确定性的测试仓库。

然后用被测插件发起一次非交互式同步，等待完成，取插件的总同步时长。

下载速度：

复用上面已上传的测试仓库，新建一个空仓库并配置被测插件。执行全量同步从远端下载这些文件，记录时长。

日常同步速度

此时应有两份仓库：一份（原始库）由测试仓库引导器生成，另一份（副本库）是从远端新下载的。

在原始库中用操作执行器执行确定性的变更即同步。脚本包含 10 个独立、顺序执行的测试用例，覆盖创建、修改、删除和重命名（移动）操作，模拟规模小但频繁的用户编辑。每个操作由 CLI 命令放行以继续。每个用例先在原始库触发一次同步，再在副本库触发一次。如果被测插件有 "Sync on change" 选项，在原始库中启用它；否则在原始库手动触发同步。

全部用例完成后，计算上述 10 次同步的最大、最小和中位时长。

同步正确性：

对原始库和副本库都运行正确性验证器，把每个库出现的错误总数加总。它代表插件的稳定性和可靠性。

基准测试工具 ​

基准测试工具位于本仓库的 scripts/benchmark/。它是一个主要与 Obsidian CLI 交互的 CLI 应用，包含五个模块：测试仓库引导器、操作执行器、正确性验证器和 Ping 测试器。

测试仓库引导器 ​

文件：scripts/benchmark/test-vault.ts

用 scripts/benchmark/test-vault.ts 初始化一个确定性的测试仓库。它先清空仓库，然后用一个随机深层嵌套文件的大型仓库模拟填充仓库：1880 个 50 字节到 50 KiB 的小文件，100 个 500 KiB 到 2 MiB 的中等文件，以及 20 个 15 MiB 到 100 MiB 的大文件。

操作执行器 ​

文件：scripts/benchmark/daily-test.ts

操作执行器以串行或并行方式执行预定义的命令操作，它遵循声明式语法遍历一个 Commands 数组：

TypeScript
type MaybePromise<T> = Promise<T> | T;
type Command =
	| string
	| { command: string; callback: (result: $.ShellPromise) => MaybePromise<void> };
type Commands = Array<Command | Array<Command>>;

命令数组中嵌套子数组里的所有命令并发执行。

命令通过执行 Obsidian CLI 命令挂接到运行中的 Obsidian 实例：

  • obsidian create path=<path> content=<content> overwrite
  • obsidian delete path=<path>
  • obsidian move path=<path> to=<destination>

日常测试流程包含 10 个测试用例，串行执行以模拟规模小但频繁的用户编辑。被测插件需要为每个测试用例执行一次同步。每次同步的时长都会被测量用于评估。

正确性验证器 ​

文件：scripts/benchmark/validator.ts

验证器用于在操作执行器执行完操作集合并完成后续同步之后，验证同步的正确性。它扫描一个仓库，校验每个文件和文件夹是否存在，缺失或多出的都标记为错误。对测试用例中追加过的文件，它还额外校验文件大小。

校验之后，它输出错误总数，以及每个错误及其原因。

Ping 测试器 ​

文件：scripts/benchmark/ping-test.ts

Ping 测试器测试连接一个 URL 时的平均 HTTP ping 延迟。它向目标发起 20 个顺序的 HTTP HEAD 请求并记录响应延迟。

全部测试结束后，它对请求延迟排序，丢弃最长的两个和最短的两个，然后对剩余 16 个样本计算平均值。
